# Phase A plan: core library and CLI

Status: validated, 2026-10-16. Design source: `docs/transpiler-design.md`. All
decisions D1 to D15 are settled there. Fable validated the first draft and
reported 22 findings. Opus accepted all 22 and resolved them in this revision.
Section 10 maps each finding to its resolution.

## 1. Goal

Phase A delivers the compiler core library and the CLI commands `check`,
`build`, and `watch`. The core lexes, parses, resolves, checks, lowers to typed
IR, validates the IR, and emits Effect-TS 4 code. The core memoizes per module
and rechecks a dependent module only when an imported interface changes (D4).

Phase A is complete when these acceptance checks pass from the repository root:

1. `deno task check` passes: format check, lint, type check, and all tests.
2. The five examples check with no diagnostics.
3. `example/log.eff` lowers to IR that is deep-equal to the parsed
   `log.ir.json`, apart from the source identifier.
4. `build` emits TypeScript for the five examples. The output equals the golden
   files, and `deno check` accepts it against `effect@4.0.5` under strict
   settings.
5. A runtime test runs the emitted `main.ts` with an in-memory `UsersLive`
   provider and gets the expected strings.
6. `deno fmt --check` accepts every golden TypeScript file unchanged (D12).
7. The IR validator reports no disagreement on every lowered fixture, and it
   rejects each mutated fixture.
8. Every error fixture produces exactly its marked diagnostic codes.
9. An incremental test shows that a body edit in `users.eff` does not recheck
   `main.eff`, and that an interface edit does.

Out of scope: the LSP server, the editor client, the playground, and hover over
the LSP. Declaration-level incremental tracking (Phase B), bundler plugins, and
readability optimizations of the emitted code are also out of scope.

## 3. Conventions

- Deno 2.9.7, TypeScript only. No `any` and no cast to `any`. Use `unknown`
  with narrowing.
- Expected failures are `Result` values, as in `typed-ir.ts`. Diagnostics are
  data. The core throws only on an internal invariant violation.
- The core is synchronous and pure. Only the CLI and test helpers touch the file
  system or run subprocesses. The core reads files through a `SourceHost`
  interface; tests use an in-memory host.
- Positions are UTF-16 code units with an exclusive end, as JavaScript strings
  index them.
- Tests use `Deno.test` and `@std/assert`. Each test runs in under one second,
  except the tests that run `deno check`, `deno fmt`, or the emitted program.
  Those tests are in files named `*_slow_test.ts` and run under
  `deno task test:slow`, which `deno task check` also runs.
- `deno.json` excludes `docs/` and `fixtures/golden/` from `deno lint`.
  Generated code cannot satisfy `no-unused-vars`, because the emitter never
  renames a source binding such as an unused handler parameter. `deno fmt`
  excludes `docs/plans/phase-a-probes/` and every `.eff` and `.effi` file.
- Tests never build inside `fixtures/`. A test copies a fixture directory to a
  temporary directory and builds there. `.gitignore` lists `fixtures/**/*.ts` and
  `fixtures/**/*.ts.map` except `fixtures/golden/**`,
  `fixtures/examples/users-live.ts`, and `fixtures/host-boundary/**`.
- Commit each part as one commit on local main. Never push. Each commit message
  ends with the attribution line that the dispatch gives.

## 5. Language decisions that Phase A fixes

The settled decisions fix most choices. This section fixes the remaining ones.
Each item marked "spec gap" goes into section 9 of the design doc as a new
question with the Phase A answer.

### 5.1 Grammar addendum (spec gap Q13)

The spec's grammar summary omits forms that the examples use. Phase A parses
these rules.

- **Keywords.** Hard keywords: `import`, `export`, `const`, `match`, `try`,
  `catch`, `if`, `else`, `true`, `false`. Contextual keywords stay valid
  identifiers elsewhere. They are `type`, `error`, `service`, and `provider` at
  the start of a declaration; `from` after an import list; `fails`, `uses`, `provides` in a
  signature. The binding `UserMissing(error) => "Guest"` in `users.eff` uses
  `error` as a name, so `error` cannot be a hard keyword.
- **Reserved words (spec gap Q12).** The lexer reports a `syntax` diagnostic
  for an identifier that JavaScript or TypeScript reserves in a strict ES
  module: `break case class continue debugger default delete do enum extends
  finally for function in instanceof new null return super switch this throw
  typeof var void while with implements interface let package private
  protected public static yield await arguments eval`. `void` stays valid as a
  type name. The emitter therefore never renames a source identifier.
- **Operators.** Version 0 has no unary operators, so `-1` and `!x` are syntax
  errors. A negative value is written `0 - 1`.
- **Record expressions.** `{ name: expr, shorthand, ... }`. One spread may
  appear first: `{ ...base, name: expr }`. A shorthand field `{ id }` means
  `{ id: id }`. A trailing comma is allowed.
- **Patterns.** A literal (string, number, `true`, `false`); `_`;
  `Some(name)`; `None`; `ErrorName(name)`; a tagged record
  `{ field: "literal", ...name }` or `{ field: "literal" }`. Nested patterns are
  errors.
- **Arrow or parenthesis.** At `(` in expression position, the parser scans to
  the matching `)`. The form is an arrow when the next significant token is `:`
  or `=>`. A newline may appear before `fails`, `uses`, and `=>` in a
  signature.
- **Brace meaning.** `{` opens a block after `=>`, after an `if` condition,
  after `else`, and after `try`. `{` after `catch` opens the handler list. `{`
  after `match subject` opens the arm list. Everywhere else `{` opens a record
  expression. A record result after `=>` needs parentheses.
- **Newlines.** A newline separates declarations, service methods, and block
  items, as a semicolon does. A newline does not end an item after a binary
  operator, `,`, `=`, `=>`, `:`, `(`, `[`, or `{`. It does not end an item
  before `fails`, `uses`, `=>`, `|>`, `else`, or `catch`.

### 5.2 Prelude

The prelude names are `fail`, `retry`, `provide`, `unbrand`, `Some`, `None`,
`map`, `filter`, and `fold`. A module cannot declare a name from this list;
the checker reports a `declaration` diagnostic. A brand type name used as a
function constructs the brand, and an error name used as a function constructs
the error.

`fail`, `retry`, `provide`, `unbrand`, `Some`, `None`, brand construction, and
error construction lower to their own IR nodes. Only `map`, `filter`, and
`fold` are specialized builtins. A builtin name may appear only in callee
position or as a pipeline stage.

### 5.3 Identities, project file, and host modules

**Module identity (D7, Q2).** The project root is the directory that contains
`effective.json`. A module's name is its path relative to the root, with POSIX
separators and without `.eff` or `.effi`, for example `users`, `example/log`,
or `host/providers`. Identities follow `typed-ir.ts`: `error:users#UserMissing`,
`service:users#Users`, `cap:users#Users.find`, `value:users#getUser`,
`type:users#User`, `local:users#getUser/id`.

All locals of a top-level function,
including nested closure parameters and block bindings, share the function's
namespace. A second local with an equal name gets the suffix `/2`, then `/3`, in
source order. Emitted error tags, service keys, and brand tokens use the part
after the colon, for example `users#UserMissing`.

**Project file.** `effective.json` at the root:

```json
{
  "host": {
    "providers": {
      "interface": "./host/providers.effi",
      "module": "./users-live.ts"
    }
  }
}
```

The import `"host:providers"` selects the key `providers`. The `interface` file
gives the Effective interface. The `module` file is the TypeScript module that
implements it. Both paths are relative to the root. A missing file or key is a
diagnostic, not an exception. In IR, `Import.module` is the imported module's
name for a relative import (`users`) and the import string for a host import
(`host:providers`).

**Host interface files (D10, Q3).** A host interface file has the extension
`.effi`. It permits `import`, `type`, `error`, `service`, and a new `provider`
declaration. It permits no `const` and no function bodies. Grammar:

```
providerDecl = ["export"] "provider" Name "provides" ServiceName ("|" ServiceName)*
               ["fails" errorSet] ["uses" requirementSet]
```

`provides` lists whole services only, because a `Layer` provides whole
services. A method name there is a diagnostic (spec gap Q14). The provider's IR
type is the `provider` variant of `Type`, with every method of each listed
service in `provides`. `fails` and `uses` are acquisition failures and
acquisition dependencies. Acquisition execution is always `effect`, as the
spec says. Fixture file:

```
import { Users } from "../users.eff"
export provider UsersLive provides Users
```

**Generated location (D6, Q7).** `users.eff` emits `users.ts` and
`users.ts.map` in the same directory. Relative import `./users.eff` becomes
`./users.ts`. A host import becomes a relative path from the generated file to
the host `module` file. A `.effi` file emits nothing.

### 5.4 Other fixed rules

**Exported constants (D13, Q4).** An exported `const` whose value is not an
arrow with full annotations requires a binding type annotation. Otherwise the
checker reports a `declaration` diagnostic.

**Unannotated module functions (Q5).** A module-level function without a result
annotation is allowed when it is not exported. It infers its result and effect
sets (`contract: "inferred"`).

**Module initialization order (spec gap Q15).** A module constant may refer to
a declaration that appears later in the source. In the checker's eager
dependency graph, a constant depends on each declaration that its initializer
references. A reference to a function adds every
declaration that the function body references, transitively. A cycle in this
graph is a `module` diagnostic. Section 6.5 orders the emitted declarations by
this graph.

**Builtin specialization (Q1).** Each distinct closed instance of `map`,
`filter`, or `fold` gets `value:<module>#$builtin/<name>/<hash>`. The hash is
the first 12 hex digits of the SHA-256 of the canonical JSON of the closed
function type. Use a small synchronous SHA-256 in TypeScript, because the core
is synchronous. The closed prelude interface is one synthetic `Import` per
module, with `module: "effective:prelude"`, `bindings: []`, `exports` equal to
the builtin ids, and `values: [{ id, name, type }]` for each builtin. The
module omits this import when it uses no builtin.

**Diagnostic codes (Q8).** A code is `<category>/<three digits>`. Categories:
`syntax`, `unknown-name`, `type-mismatch`, `failure-contract`,
`requirement-contract`, `execution-mode`, `pattern`, `declaration`, `module`,
`host-boundary`. `src/core/diagnostics.ts` holds the one registry of codes with
a short description each. Each part registers only the codes that it emits. A
test checks that each registered code has at least one error fixture.

**Optional and Option fields (Q9).** A `?` field emits
`Schema.optionalKey(T)`. A required `Option<T>` field emits
`Schema.Option(T)`; the probe passed. Reading an optional field emits
`Option.fromUndefinedOr(record.field)`.

**Providers in provide (Q10).** `provide` accepts only a provider declared in a
host interface file.

**int arithmetic (D14, Q6).** The emitter wraps the result of each `+`, `-`,
and `*` with two `int` operands in a module-local helper `$int`. The emitter
defines `$int` once per module, only when used. The helper body is in `scheme.ts`. A throw inside
`Effect.gen` becomes a defect, which the spec requires. Division never uses
the helper, and the emitter imports no runtime package.

**Record compatibility (spec gap Q11).** A record type is compatible with
another record type only when both have the same field names, the same
optional flags, and compatible field types. Phase A has no width subtyping.

### 5.5 Lowering rules (part A4)

- A module `const` whose value is syntactically an arrow lowers to a
  `FunctionDecl`. An annotated binding with an arrow value, such as
  `const f: (x: int) => int = (x) => x + 1`, lowers to a `FunctionDecl` with
  `contract: "explicit"`. Every other `const` lowers to a `ConstantDecl`.
- A block that ends with a binding, or has no items, has the result
  `literal null` with type `primitive unit`. The emitter prints it as
  `undefined`.
- A `Parameter.span` covers the name and its annotation. In the fixture,
  `message: string` is 145 to 160.
- A pipeline lowers to a block. The base value and each stage except the last
  get a `bind` step whose binding is named `$p<n>`, with id
  `local:<mod>#<fn>/$p<n>`. The binding uses the span of the left expression,
  and the call keeps the stage span. The number `<n>` skips a name that an
  identifier of the module already uses (correction of 2026-10-17).
- Acceptance check 3 compares parsed JSON with deep equality. Key order differs
  between fixture nodes, so a text comparison is wrong.

### 5.6 Fresh names

The emitter collects every identifier in the module and in its IR first. It
then allocates each generated name and skips a name that is taken. Generated
names: `$t<n>` temporaries, `$s` service parameters, `$int`, the schema helper
`$Int`, and `<Name>$host`. The lowering names the pipeline bindings `$p<n>`
and skips each name that the module uses (section 5.5). The imports from `effect` (`Effect`, `Context`,
`Layer`, `Option`, `Schema`) go through the same check.

When a module declares
one of these names, the emitter imports the Effect module under an alias such
as `Option$1`. A foreign declaration that the emitter must print uses its
source import name when the module imports it. Otherwise the emitter imports it
under its own name when that name is free, and under `<Name>$<n>` when it is
not.

## 6. Emission scheme (parts A6a and A6b)

The emitter reads only `ModuleIR` plus the project configuration. Every IR node
carries `execution`. `docs/plans/phase-a-probes/scheme.ts` shows the forms.

### 6.1 Three emission functions

- `pure(e)`: a TypeScript expression for a pure-mode node. Its children are
  pure, except closure bodies, which emit as their own functions.
- `inGen(e)`: a TypeScript expression valid inside a generator body. It yields
  each effect where the source evaluates it, so JavaScript order preserves the
  spec's evaluation order.
- `asEffect(e)`: a TypeScript expression of type `Effect.Effect<...>`.

A **leaf effect** is a `call` of an effectful function value, `perform`, `fail`,
`retry`, `provide`, or `catch`. Rules:

| Node | `inGen(e)` | `asEffect(e)` |
| --- | --- | --- |
| Pure-mode node | `pure(e)` | `Effect.succeed(pure(e))` |
| Leaf effect, all evaluated children pure | `yield* leaf` | `leaf` |
| Leaf effect, an effectful evaluated child | `yield* Effect.gen(function* () { const $t0 = inGen(child0); ...; return yield* leaf($t0, ...) })` | the same `Effect.gen` without the outer `yield*` |
| Other effect-mode node | the node with children through `inGen` | `Effect.gen(function* () { return inGen(e) })` |

**Evaluated children.** For `call`, the evaluated children are the callee and
the arguments, in that order. For `perform` and `fail`, they are the arguments
or the error value. When the hoist rule applies, the emitter hoists every
evaluated child up to and including the last effectful one, in source order.
This keeps a pure defect, such as an `$int` overflow, in its left-to-right
position relative to effects.

**Deferred positions.** `catch` has no evaluated children. Its body and its
handlers appear only through `asEffect`, so the handlers exist before the
protected block runs, as the spec requires. The `job` of `retry` and `provide`
is a closure construction, which is pure and evaluates at once; its body is
deferred by `Effect.suspend`. A pure job is lifted first, for example
`Effect.suspend(() => Effect.succeed(2))`, because `suspend` needs an effect
(correction of 2026-10-17).

### 6.2 Leaf forms

| IR node | Leaf expression | Source of the form |
| --- | --- | --- |
| `call` of effectful function | `f(a, b)` | book, `pay` |
| `perform` | `Users.use(($s) => $s.find(a))` | book, `getUser` |
| `fail` | `Effect.fail(new UserMissing({ id }))` | book |
| `retry` | `Effect.retry(Effect.suspend(job), { times: 2 })` | spec, retry section |
| `provide` | `Effect.provide(Effect.suspend(job), UsersLive$host)` | spec, modules section |
| `catch` | `asEffect(body).pipe(Effect.catchTags({ "users#UserMissing": (error) => asEffect(handler), ... }))` | probe `catch-tags.ts` |

`catch` uses one `Effect.catchTags` call with all handlers. A chain of
`Effect.catchTag` calls is wrong: a later handler would catch a failure that an
earlier handler raises. The spec requires that a handler failure reaches the
caller. `deno check` gives both forms the same type, so only a runtime test can
detect the difference. Part A6a adds that runtime test.

### 6.3 Control forms

- `if` in pure mode is `c ? a : b`. In a generator it is
  `inGen(c) ? inGen(a) : inGen(b)`. Only the selected branch yields.
- `match` on an option is
  `Option.match(subject, { onNone: () => arm, onSome: (x) => arm })`. In pure
  mode the arms are `pure`. In effect mode the subject is `inGen`, the arms are
  `asEffect`, and the whole expression is yielded once.
- `match` on literals, wildcards, error patterns, and tagged records uses a
  selector arrow over the subject:
  `(($t0) => $t0.kind === "circle" ? ((circle) => arm)($t0) : armB)(subject)`.
  An error pattern tests `$t0._tag === "mod#ErrorName"`. A literal match tests
  `$t0 === literal` and ends with the `_` arm. In effect mode the arms are
  `asEffect`, and the result is yielded once. Probes `extent` and `extentE`
  show both modes.
- `block` as a function body is a statement list. Each `bind` step is a
  `const`, each `evaluate` step is an expression statement, and the result is a
  `return`. In effect mode the function body is
  `Effect.gen(function* () { ... })`. A nested block in pure mode is an
  immediately invoked arrow. In effect mode it is a yielded nested `Effect.gen`.
- Every emitted `const`, including `bind` steps, pipeline bindings, and `$t`
  temporaries, carries a type annotation from the type printer. Without it,
  TypeScript widens literal fields and tuple literals; probe `widen.ts` fails
  with TS2322.

### 6.4 Parentheses around `yield*`

The printer chooses parentheses by parent position, so that `deno fmt` leaves
the output unchanged. The rule was measured with `deno fmt` on the probes.

| Parent position | Form |
| --- | --- |
| `const` initializer, expression statement, call argument, array element, record field value, `return` argument | `yield* x`, no parentheses |
| Member access object, binary operand, conditional test or branch, `$int` argument operand | `(yield* x)` |

### 6.5 Declarations and their order

The emitter prints declarations in this order. Inside each group it keeps
source order, except where a dependency requires a change.

1. Type, error, and service declarations, in topological order over their type
   references. Probe `tdz.ts` shows that a schema constant used before its
   definition fails with TS2448.
2. Function declarations. Their bodies are deferred, so their order is free.
3. Module constants, in topological order over the eager dependency graph from
   section 5.4.

| Source | Emitted TypeScript |
| --- | --- |
| `type X = { ... }` | `const X = Schema.Struct({ ... })` and `type X = typeof X.Type` |
| Literal union | `Schema.Literals([...])` |
| Union of records | `Schema.Union([...])` with inline `Schema.Struct` members |
| `type X = Brand<string>` | `Schema.String.pipe(Schema.brand("mod#X"))` |
| `int` in a schema | `$Int`, defined once per module as the book's `Int` schema, when used |
| Array, tuple, option, unknown in a schema | `Schema.Array`, `Schema.Tuple`, `Schema.Option`, `Schema.Unknown` |
| Alias that contains a function or provider type | a TypeScript `type` alias only |
| `error E = { ... }` | `class E extends Schema.TaggedError<E>()("mod#E", { ... }) {}` |
| `service S { ... }` | `class S extends Context.Service<S, { readonly m: (...) => Effect.Effect<...> }>()("mod#S") {}` |
| Brand construction `OrderId(v)` | `OrderId.make(v)`; probe `brand-d.ts` passed |
| `unbrand(v)` | `v` |
| `Some(v)`, `None` | `Option.some(v)`, `Option.none()` |
| Record update | `{ ...base, field: value }` |
| `map`, `filter`, `fold` | `.map`, `.filter`, `.reduce(callback, initial)` |
| Host import | `import { UsersLive } from "./users-live.ts"` plus `const UsersLive$host: Layer.Layer<Users> = UsersLive` |
| Pure function | `const f = (a: A): R => pure(body)` |
| Effectful function | `const f = (a: A): Effect.Effect<R, E, Rq> => asEffect(body)` |
| Function with inferred contract | no result annotation |

`provide` refers to `UsersLive$host`, not to `UsersLive`, so that the assertion
constant is used. A mismatch between the registry and the host module then
appears on the assertion line. The span table maps that line to the `.eff`
import span, and the CLI reports such a `deno check` error with the category
`host-boundary`.

The emitter adds `export` to every declaration that the source exports and to
every declaration that the module interface reaches (I8).

### 6.6 Type printer

| IR type | TypeScript |
| --- | --- |
| `int`, `number` | `number` |
| `string`, `boolean`, `unknown`, `never` | the same name |
| `unit` | `void` |
| Literal | the literal |
| Array | `ReadonlyArray<T>` |
| Tuple | `readonly [A, B]` |
| Option | `Option.Option<T>` |
| Record | `{ readonly f: T; readonly g?: U }` |
| Union | members joined with `\|` |
| Named | the local name, or the import name from section 5.6 |
| Pure function | `(a: A) => R` |
| Effectful function | `(a: A) => Effect.Effect<R, E, Rq>` |
| Provider | `Layer.Layer<S1 \| S2, E, Rq>` |

`ReadonlyArray` matters: a parameter printed as `User[]` cannot receive the
`ReadonlyArray<User>` that a service returns.

**Order inside Effect types.** `E` and `R` follow sorted identity order for
every contract. The IR stores effect sets sorted, and the emitter reads only the
IR, so the source order of the clauses is not available. `R` groups
capabilities by service, in sorted service identity order, and replaces an
earlier rule that used source order.

An empty `R` is left out, for example
`Effect.Effect<void, StoreUnavailable>`. An empty `E` before a nonempty `R`
prints `never`, for example `Effect.Effect<Order, never, Orders>`. When both
are empty the type is `Effect.Effect<A>`, where `A` is the result type.

### 6.7 Span table, source map, and formatting

While it prints, the emitter records `(generatedStart, generatedEnd,
sourceSpan)` triples in UTF-16 units for every IR node it prints.
`users.ts.map` is a version 3 source map derived from the table.

Formatting (D12): the printer has one fixed style. A slow test runs
`deno fmt --check` over the golden files. If a construct cannot reach a fixed
point, the implementer stops and reports the construct with the `deno fmt`
diff. The implementer does not exclude files from formatting on their own.

## 7. Checker scope (parts A3a and A3b)

The checker implements the spec sections "Data and types" through "Modules and
boundaries" and the equations in "Equations and validation". The hard points:

- `int` is a subtype of `number`. Integral literals infer `int` unless the
  context requires `number`. Contextual typing keeps expected literal
  alternatives.
- `never` fits every result type. `if` needs an `else`. Branches need a common
  type.
- Each expression gets a type, a failure set, a requirement set, and a mode.
  Sets are sorted arrays of identity strings. Only types are interned.
- Mode inference per module-local strongly connected component starts at pure
  and iterates to a fixed point, with a round cap. A diagnostic from inside the
  iteration appears once, after the last round.
- Explicit contracts: body failures and requirements must fit the declared
  sets. Nonempty declared sets lift the interface to effect mode.
- Callbacks of `map`, `filter`, and `fold` require pure mode and empty sets. An
  unbodied callback parameter has effect mode.
- `retry` and `provide` take zero-argument functions. `times` is a finite
  nonnegative safe integer literal.
- `catch` removes handled tags. It rejects duplicate handlers and handlers for
  tags absent from the protected set.
- `match` requires complete coverage. It rejects unreachable arms and foreign
  constructors. An unbounded primitive domain needs a final `_`.
- Module constants need a pure active mode and empty active sets. The eager
  dependency graph from section 5.4 has no cycle.
- Record construction rejects missing, duplicate, and unknown fields.
- Error recovery follows design section 6.4. An error node has the error type,
  which is compatible with everything, has empty sets, and has pure mode. A
  diagnostic caused by an error-typed operand is suppressed.

Side tables: for each declaration body, one map from syntax node id to
`{ type, failures, requirements, mode }`, and one map from name node id to its
resolved target. The core exposes `typeAt(file, offset)`, which returns the
innermost node's type and contract as text. One test covers it. The LSP uses it
later.

CLI contract (A7):

- `effective check [root]` prints diagnostics and exits 0 when it finds none, 1
